1. WHAT IS THIS PROJECT & WHY WE CHOSE IT?
------------------------------------------
"The IPL Mega Auction is a high-stakes, multi-million-dollar event where fast 
decisions, strict budget limits, and instant updates make or break a team.
We chose to build this system because it represents a complete real-world 
engineering challenge: combining live financial transactions, concurrent 
bidding by multiple franchises, and sub-second real-time synchronization."


2. WHAT PROBLEM DOES IT SOLVE?
------------------------------
"In any live auction system, three major technical problems occur:

  1. Race Conditions: When two teams click 'Bid' at the exact same millisecond, 
     ordinary systems cause double bids or inconsistent prices.
  2. Financial & Squad Limits: Teams must strictly stay within their Rs. 120 Crore 
     purse and follow team squad balance rules.
  3. Network Lag: Normal web apps use slow refresh/polling. In live bidding, 
     every team must see the updated hammer price in under 50 milliseconds.

Our project solves all of these using database concurrency locking, 
Spring Security JWT tokens, and STOMP WebSockets."


3. MY ROLE, WHAT I USED & WHY:
------------------------------
- My Role: System Orchestration, REST Architecture, and Core Backend APIs.
- Tech Used: Java 17, Spring Boot 3, Spring MVC.
- Why I Used It:
    * Spring Boot gives enterprise-level dependency injection and robust 
      transaction management (@Transactional).
    * Handles all CRUD operations for Teams, Players, and Auction rounds.
    * Implemented Global Exception Handling (@RestControllerAdvice) to return 
      clean, structured JSON error messages for invalid bids or budget limits.

MEMBER 2: SECURITY & AUTHENTICATION SPECIALIST

[MEMBER 2 SPEAKS]

"Thank you, [Leader Name]!
Hello everyone, I am [Member 2 Name], and my role was Security & Authentication Specialist."


1. MY ROLE, WHAT I USED & WHY:
------------------------------
"In a multi-team bidding system, unauthorized bids or team impersonation 
(like bidding on behalf of CSK while logged in as MI) cannot be allowed. 
My job was to ensure rock-solid authentication and Role-Based Access Control."

- Tech Used: 
    * Spring Security 6
    * Stateless JWT (JSON Web Tokens) with HMAC-SHA256
    * BCrypt Password Hashing

- Why I Used It:
    * Traditional server sessions consume memory and do not work well with 
      distributed WebSocket connections.
    * JWTs are stateless, tamper-proof, and fast. The token directly carries the 
      team owner's identity and authorized franchise ID.

- What I Built:
    * SecurityConfig.java: Defined strict CORS rules and protected endpoints.
    * TokenAuthenticationFilter.java & TokenUtil.java: Intercepts every HTTP 
      request, verifies the JWT signature, and authenticates the user.
    * WebSocketSecurityInterceptor.java: Validates user identity on live socket 
      connection frames so unauthorized clients cannot inject fake bids.

MEMBER 3: DATABASE SCHEMA & CONCURRENCY DEVELOPER
================================================================================

[MEMBER 3 SPEAKS]

"Thank you, [Member 2 Name]!
Hello everyone, I am [Member 3 Name], and I served as the Database Architect & 
Concurrency Developer."


1. MY ROLE, WHAT I USED & WHY:
------------------------------
"The biggest technical bottleneck in any live auction is handling concurrent 
bids at the exact same moment without data corruption or double spending."

- Tech Used: 
    * MySQL / In-Memory H2 Database
    * Spring Data JPA & Hibernate ORM
    * Pessimistic Database Row Locking (@Lock(LockModeType.PESSIMISTIC_WRITE))

- Why I Used It:
    * Optimistic locking causes annoying retry errors for users during heavy bidding.
    * Pessimistic Locking locks the specific Player and Team rows at the SQL level 
      (SELECT ... FOR UPDATE). This forces incoming bids to be processed one-by-one 
      in exact chronological sequence, completely eliminating race conditions.

- What I Built:
    * Relational Entities: Designed Player, Team, User, Bid, and Auction models.
    * Atomic Purse Deductions: Deducts team purse and updates rosters safely.
    * DataInitializer.java: Pre-seeds the database with 10 official IPL franchises, 
      starting purse amounts, and marquee players with their base prices.

------------------------------

        - Bidding with insufficient balance
