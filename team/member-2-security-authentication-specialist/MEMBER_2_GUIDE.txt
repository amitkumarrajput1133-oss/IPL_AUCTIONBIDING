3. TOOLS YOU USE
--------------------------------------------------------------------------------
- Spring Security 6: Security framework that locks and unlocks URLs.
- BCrypt: Scrambles passwords into secure, one-way hashes.
- JWT (JSON Web Token): Digital 24-hour passes given to users after login.
- Postman: To test login, registration, and Bearer token headers.


4. YOUR CODE FILES & WHAT THEY DO (IN PLAIN ENGLISH)
--------------------------------------------------------------------------------
- config/SecurityConfig.java: 
  The master security rulebook. Disables CSRF (because we are stateless), sets 
  public URLs (/api/auth/**), and locks private URLs behind roles.

- config/TokenUtil.java: 
  The digital token maker. Generates a 24-hour pass with username, role, and 
  team ID sealed with a secret key. Also verifies token authenticity and expiry.

- config/TokenAuthenticationFilter.java: 
  Sits at the entrance of every HTTP request. Reads the "Authorization: Bearer <token>" 
  header, verifies the token, and sets the user in Spring's SecurityContext.

- controller/AuthController.java: 
  Provides URLs for /api/auth/register and /api/auth/login. Returns a JWT token 
  when user credentials match.

- config/WebSocketSecurityInterceptor.java & WebSocketHandshakeInterceptor.java: 
  Verifies the JWT token when users connect to live auction WebSockets.

8. TOP QUESTIONS THE MENTOR CAN ASK YOU & HOW TO ANSWER
--------------------------------------------------------------------------------
Q1: Why is CSRF disabled in your SecurityConfig?
Ans: CSRF attacks target browser cookies in stateful sessions. Because our 
     backend uses stateless JWT authentication sent via HTTP headers, cookies 
     are not used, making CSRF disabling completely safe.

Q2: What information is stored inside your JWT token?
Ans: The token payload stores the username, role (ADMIN or TEAM_OWNER), 
     teamId, and the expiration timestamp (24 hours). It is digitally signed 
     so clients cannot alter it.

Q3: How does the server verify passwords?
Ans: We never store plain text passwords. We use BCryptPasswordEncoder.matches(
     rawPassword, encodedPassword). BCrypt automatically handles salt generation 
     to protect against dictionary attacks.

Q4: How do you stop a regular Team Owner from calling Admin APIs?
Ans: In SecurityConfig.java, we define:
     .requestMatchers('/api/auction/active/**').hasRole('ADMIN').
     If a user with ROLE_TEAM_OWNER calls it, Spring Security blocks it with 
     an HTTP 403 Forbidden.
